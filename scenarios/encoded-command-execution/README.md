# Encoded Command Execution

## Overview

This scenario simulates multiple encoded command execution techniques commonly used by adversaries to conceal malicious activity from analysts and security controls.

Encoded command execution is frequently observed during post-compromise operations where attackers attempt to obscure payload contents through encoding and decoding mechanisms before execution.

The objective of this simulation was to understand:

* How encoded payloads execute on Linux systems
* How decoding activity appears in telemetry
* How process lineage changes across execution methods
* How discovery commands manifest after payload execution
* How behavioral detections can identify encoded execution activity despite implementation differences

The scenario follows the complete detection engineering lifecycle from simulation through validation.

---

# Objectives

The simulation was designed to:

* Recreate encoded payload execution techniques
* Collect process execution telemetry
* Observe decoding and interpreter activity
* Reconstruct attack sessions from telemetry
* Analyze attacker behavior
* Map observed behavior to MITRE ATT&CK
* Engineer behavioral detections
* Validate Sigma detection coverage across multiple variants

---

# Scenario Architecture

The simulation consists of four encoded execution variants.

Each variant executes the same payload but uses a different execution method.

```text
Variant 1
Encoded Payload
      ↓
Direct Decode
      ↓
Shell Execution

Variant 2
Encoded Payload
      ↓
Decode To File
      ↓
Permission Change
      ↓
Execution

Variant 3
Encoded Payload
      ↓
Python Decoder
      ↓
Shell Execution

Variant 4
Encoded Payload
      ↓
Multi-Stage Decode
      ↓
Shell Execution
```

---

# Payload Behavior

All variants ultimately execute the same post-decode payload.

The payload performs basic environment and host discovery operations.

Commands executed:

```bash
whoami
id
hostname
uname -a
ps aux
touch /tmp/.enc_exec_marker
curl 127.0.0.1:8080
```

These commands were intentionally selected because they resemble common reconnaissance activity performed immediately after gaining command execution.

---

# Variant 1 – Direct Pipe Execution

## Description

The payload is Base64 encoded and decoded directly into a shell interpreter.

Execution flow:

```text
bash
  ↓
base64 -d
  ↓
bash
  ↓
payload commands
```

## Purpose

Demonstrates in-memory style execution where decoded content is immediately executed without reconstruction as a file.

---

# Variant 2 – File Reconstruction

## Description

The payload is decoded and written to a temporary file before execution.

Execution flow:

```text
base64 decode
      ↓
/tmp/decoded_payload.sh
      ↓
chmod +x
      ↓
execution
```

## Purpose

Demonstrates a staged execution workflow commonly used when attackers reconstruct payloads on disk prior to execution.

---

# Variant 3 – Python Decode

## Description

Python is used as the decoding mechanism before invoking the decoded payload.

Execution flow:

```text
bash
  ↓
python3
  ↓
bash
  ↓
payload commands
```

## Purpose

Demonstrates the use of scripting languages as execution intermediaries and highlights interpreter handoff behavior.

---

# Variant 4 – Multi-Stage Decode

## Description

The payload is encoded multiple times and requires multiple decode operations before execution.

Execution flow:

```text
bash
  ↓
base64
  ↓
base64
  ↓
bash
  ↓
payload commands
```

## Purpose

Demonstrates layered payload obfuscation and multiple decode stages prior to execution.

* Temporary file activity
* Payload execution logs
* HTTP listener logs
* TCP network captures
* Process lineage evidence

# Telemetry Analysis

Telemetry analysis focused on:

* Parent-child process relationships
* Decode operations
* Script reconstruction activity
* Interpreter execution chains
* Discovery command execution
* Network activity generated by the payload

Each variant was reconstructed from raw telemetry to identify behavioral similarities and differences.

---

# Investigation Outcomes

Investigation of the collected telemetry revealed several recurring behaviors.

Observed behaviors included:

* Encoded content being decoded before execution
* Shell interpreters executing decoded content
* Temporary file reconstruction
* Python-based payload decoding
* Multi-stage decoding workflows
* Immediate host and user discovery activity
* Short-lived command execution chains
* Local HTTP communication used as execution validation

Although execution methods varied, all variants converged on similar post-execution behavior.

---

# Threat Mapping

Observed activity was mapped to ATT&CK techniques associated with encoded payload execution, command interpretation, and discovery activity.

Primary ATT&CK techniques:

* T1059 – Command and Scripting Interpreter
* T1140 – Deobfuscate/Decode Files or Information
* T1027 – Obfuscated/Compressed Files and Information
* T1033 – System Owner/User Discovery
* T1082 – System Information Discovery
* T1057 – Process Discovery

Threat mapping demonstrated that encoded execution frequently serves as a precursor to post-compromise reconnaissance.

---

# Detection Engineering Outcomes

Analysis of the collected telemetry identified several repeatable detection opportunities.

Key behavioral indicators included:

* Base64 decode activity
* Multiple decode stages
* Python-based payload decoding
* Temporary payload reconstruction
* Interpreter execution chains
* Discovery commands executed immediately after decoding
* Correlation of decoding activity with reconnaissance behavior

These observations were used to develop behavioral detection logic and Sigma rules.

---

# Validation

Detection validation was performed against all four variants.

Validation confirmed that:

* Telemetry captured the simulated behavior
* Process lineage was reconstructable
* Investigation findings were supported by evidence
* ATT&CK mappings aligned with observed behavior
* Detection logic accurately represented execution patterns
* Sigma detections successfully identified the simulated activity

The scenario demonstrated that behavior-based detection remains effective even when payload execution methods vary.

# Conclusion

This scenario demonstrates how encoded command execution can be implemented through multiple execution paths while producing consistent post-execution behavior.

Despite differences in decoding methods, file reconstruction techniques, and interpreter usage, all variants generated observable telemetry that enabled investigation, ATT&CK mapping, behavioral analysis, and successful detection engineering.

The scenario reinforces the importance of focusing on behavioral patterns and process relationships rather than relying solely on specific command strings or payload implementations.
