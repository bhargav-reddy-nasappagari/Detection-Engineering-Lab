# Beaconing / Periodic Callback Timeline

## Scenario Summary

This simulation emulated a simple beaconing mechanism where a shell process periodically executed HTTP callbacks using curl against a local HTTP server.

The objective was to generate recurring outbound application-layer traffic that could be reconstructed through process execution telemetry and server-side logs.

## Detection-Relevant Behaviors

### Recurring Network Utility Execution

The same parent process repeatedly spawned:

```text
curl
```

at nearly identical intervals.

### Consistent Destination

Every callback targeted:

```text
127.0.0.1:8080
```

and requested:

```text
/checkin
```

### Timing Regularity

Observed interval:

```text
60 seconds
```

with minimal drift.

### Long-Lived Parent Process

A single bash process persisted throughout the callback lifecycle and continuously generated network activity.

---

## Detection Conclusion

The telemetry demonstrates a classic periodic callback pattern:

```text
Long-lived shell
        ↓
curl HTTP request
        ↓
sleep 60
        ↓
curl HTTP request
        ↓
sleep 60
        ↓
(repeats)
```

This behavior aligns with:

ATT&CK T1071 – Application Layer Protocol

and provides sufficient evidence for beaconing-oriented detection analytics based on recurring process execution and timing correlation.
